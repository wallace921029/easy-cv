## 1. 产品概述

### 1.1 定位

Easy CV 是一个自托管、供个人私用的在线文本剪贴板：在任意设备打开网页，按下 ⌘/Ctrl + V 就能把一段文字存进自己的账户，再到另一台设备上一键复制回来。

### 1.2 典型场景

- **电脑 → 手机**：把链接、地址、一段代码从电脑发到手机。
- **手机 → 电脑**：手机上复制的文字、验证码，在电脑上取用。
- **常用片段**：常用命令、回复模板置顶，随取随用。
- **多人共用**：家人或小团队共用一台服务器，每人一个账户，数据互相隔离。

### 1.3 设计原则

1. **快**：粘贴即保存、无需确认；点击即复制。高频操作都只要一步。
2. **私有**：每个用户只能看到自己的内容，管理员也看不到他人内容；不提供任何对外分享能力。
3. **简单**：一个容器、一个 SQLite 文件，备份就是复制数据目录。

### 1.4 非目标（v0.x 不做）

- 图片、文件：v0.x 只处理纯文本。
- 分享 / 公开链接：内容只供账户本人使用。
- 自动过期、阅后即焚：条目永久保存，直到用户自己删除。
- 实时推送：其他设备上的改动在切回页面时刷新，不做 WebSocket / SSE。
- 在后台自动同步系统剪贴板（需要原生客户端，网页做不到）。
- 保留富文本 / HTML（只存纯文本，避免 XSS 和排版问题）。
- 多管理员、团队空间、协作编辑。
- 依赖邮件的功能（找回密码、邮箱验证），不引入 SMTP。
- 细粒度权限、存储配额。

## 4. 功能详述

### 4.1 主页（剪贴板列表）

**布局**

- 顶栏：Logo · 搜索框 · 「新建」按钮 · 用户菜单（账户设置、管理后台〔仅管理员可见〕、主题、退出）。
- 列表：单列卡片，最大宽度约 768px，居中。
  - 「已置顶」分组在最前，全部加载，按置顶时间倒序。
  - 「最近」分组在后，按**最近活跃时间**倒序（创建或重复粘贴时刷新，编辑不刷新），无限滚动，每次 30 条。
- 移动端：卡片全宽，右下角悬浮「+」按钮。

**卡片**

- 内容：最多显示 8 行，超出部分渐隐并显示「展开」；保留换行和空格；URL 自动识别为链接（新标签页打开）。
- 元信息：时间 · 字数；按需显示置顶标记和「已编辑」。
- 「复制」按钮始终可见。
- 「⋯」菜单：置顶 / 取消置顶 · 编辑 · 删除。

**时间显示**（day.js，`zh-cn` 语言包 + `relativeTime` 插件）

| 距今 | 显示 |
| --- | --- |
| < 1 分钟 | 刚刚 |
| < 1 小时 | N 分钟前 |
| 今天 | 今天 14:32 |
| 昨天 | 昨天 14:32 |
| 今年内 | 9月1日 14:32 |
| 更早 | 2025-09-01 |

鼠标悬停显示完整时间（`2026-09-14 14:32:05`）；相对时间每分钟自动刷新。

### 4.2 创建条目

#### 4.2.1 全局粘贴（核心交互）

**触发**

- 监听页面的 `paste` 事件，而不是监听按键。因此 ⌘/Ctrl + V、右键「粘贴」、浏览器菜单里的粘贴都能触发。`paste` 事件不要求 HTTPS，通过 IP 访问时同样可用。
- 以下情况不拦截，交给浏览器默认行为：
  - 焦点在输入框、文本域或可编辑区域内；
  - 有对话框打开；
  - 当前页面不是主页。

**内容识别**（从上往下匹配）

1. 剪贴板里有非空的 `text/plain` → 创建一条文本。
   从 Office / WPS 复制表格时剪贴板里会同时有图片和文字，这里只取文字。
2. 只有图片或文件 → 提示「目前只支持保存文本」。
3. 什么都没有 → 提示「剪贴板中没有可保存的内容」。

**处理规则**

- 只有空白字符的文本不保存；其他文本原样保存（不去首尾空格，保留缩进）。
- **去重**：同一用户已有完全相同的文本（按 SHA-256 比较）时不新建，而是把原条目移到「最近」最前（如果是置顶条目则原地高亮），并提示「内容已存在，已移到最前」。去重只发生在创建时，编辑不受影响。
- 超过单条上限时提示「文本超过 1 MB 上限」。

**反馈**

- 乐观更新：新条目立即出现在列表顶部并短暂高亮；toast「已保存」，附「撤销」。
- 保存失败时条目标红，提供「重试」和「移除」。

#### 4.2.2 新建按钮

- 点击「新建」打开对话框（桌面端居中弹窗，移动端底部抽屉）：
  - 多行文本框，自动获得焦点；
  - 「读取剪贴板」按钮：只在 HTTPS 下且浏览器支持时显示。这是移动端最快的创建方式，iOS 会弹出系统的「粘贴」确认气泡。
- ⌘/Ctrl + Enter 保存；Esc 关闭，有未保存内容时二次确认。
- 在对话框的文本框里粘贴就是普通粘贴，不会触发自动创建。

#### 4.2.3 限制（可通过环境变量调整）

| 项目 | 默认值 |
| --- | --- |
| 单条文本 | 1 MB |
| 每用户条目数 | 不限 |

### 4.3 使用条目

**复制**

- **单击卡片即复制**，这是最高频的操作。以下情况不触发：用户正在卡片里选择文字；点击的是链接（直接打开链接）。
- 实现：HTTPS 下使用 `navigator.clipboard.writeText`；通过 HTTP / IP 访问时自动降级为 `document.execCommand('copy')`，用户无感知。
- 成功反馈：复制按钮图标变成 ✓，持续 1.5 秒，同时 toast「已复制」。
- 复制不改变排序，避免列表跳动。

**编辑**

- 「⋯」→「编辑」，打开和新建相同的对话框并预填内容。
- 保存后原地更新，不改变排序，元信息显示「已编辑」。

**置顶**

- 切换置顶状态。置顶条目进入「已置顶」分组，按置顶时间倒序；取消置顶后回到「最近」分组的最前面。

**删除**

- 立即从列表移除，toast「已删除」附「撤销」（5 秒内有效）。
- 服务端软删除；软删除超过 24 小时的条目由定时任务物理清理。
- P1「清空未置顶」：二次确认，确认框里显示将删除的条数。

### 4.4 搜索

- 顶栏搜索框，输入后防抖 300ms；匹配文本内容，不区分大小写；结果中高亮关键词。
- 搜索时不分组，统一按时间倒序。
- 实现：v0.0.1 用 `LIKE`（转义 `%` 和 `_`）；数据量过万后再考虑 FTS5（trigram 分词可支持中文）。

### 4.5 多设备同步

- 页面重新可见时（切回标签页、解锁手机）自动刷新列表。换到另一台设备查看的动作本身就伴随着切换页面，这能覆盖绝大多数场景。
- 不做实时推送：同一时刻在两台设备上都开着页面时，另一台要切回页面后才会看到变化。

### 4.6 账户

**字段规则**

| 字段 | 规则 |
| --- | --- |
| 用户名 | 3–32 位，只允许字母、数字、`_`、`-`；不区分大小写且唯一；注册后不可修改 |
| 密码 | 8–128 位，不强制复杂度（参考 NIST 800-63B）；输入框可切换明文显示 |
| 邀请码 | 校验时忽略大小写、空格和连字符 |

**注册 `/register`**

- 只有开放注册时可用；否则显示「当前未开放注册，请联系管理员」。
- 字段：用户名、密码、确认密码、邀请码。
- 支持 `/register?code=XXXX` 自动填入邀请码，管理员可以直接分享这个链接。
- 注册成功后自动登录，进入主页。

**登录 `/login`**

- 用户名 + 密码。登录失败统一提示「用户名或密码错误」，不暴露用户是否存在。
- 账户被停用时，只有在密码正确的情况下才提示「账户已被停用，请联系管理员」。
- 登录状态保持 30 天，每次访问自动续期。
- 未登录访问任何页面都跳转到登录页，登录后回到原页面。
- 开放注册时显示「没有账户？注册」入口，未开放时隐藏。

**账户设置 `/settings`**

- 修改密码：需要输入当前密码；成功后其他设备上的登录全部失效。
- 主题：跟随系统 / 浅色 / 深色。
- P1：「退出所有设备」。

**忘记密码**

- 普通用户：联系管理员在后台重置。
- 管理员：在服务器上执行 CLI 命令重置（见 [§7.5](#75-运维命令)）。

### 4.7 系统初始化（首个管理员）

1. 部署者在 `.env` 中设置 `ADMIN_INVITE_CODE`（不少于 8 位）。
2. 服务启动时，如果数据库里没有任何用户，而该变量未设置或长度不足 → **拒绝启动**，日志中给出明确提示。这样可以避免出现「谁先打开页面谁就是管理员」的空窗期。
3. 系统未初始化时，访问任何页面都跳转到 `/setup`「创建管理员账户」：用户名、密码、确认密码、初始化码。
4. 提交后，服务端在同一个事务里确认用户表仍然为空，并以常量时间比较校验初始化码；通过后创建管理员并自动登录。多人同时提交时只有第一个会成功。
5. 初始化完成后：
   - `/setup` 永久不可用，访问时跳转到登录页；
   - `ADMIN_INVITE_CODE` 永久失效，即使还留在 `.env` 里也不起任何作用，日志会提示可以删除；
   - 注册默认处于**关闭**状态。
6. 初始化码和 §4.8.2 的注册邀请码相互独立：前者只用来创建管理员，后者由管理员在后台管理。

### 4.8 管理后台 `/admin`（仅管理员）

#### 4.8.1 用户管理

表格列：用户名 · 角色 · 状态 · 条目数 · 注册时间 · 最近登录。

| 操作 | 说明 |
| --- | --- |
| 停用 / 启用 | 停用后立即清除该用户的所有登录会话，之后无法登录，数据保留；启用后恢复正常 |
| 重置密码 | 管理员输入新密码，或点击「生成」得到一个随机密码（只显示一次，可复制）；该用户所有会话失效 |
| 删除 | 需要输入该用户名进行二次确认；永久删除用户和他的全部条目，不可恢复 |
| 新建用户（P1） | 注册关闭时也能直接给家人、同事开账号 |

- 管理员自己那一行不显示任何操作。
- 管理员只能看到条目数量，看不到任何条目内容。

#### 4.8.2 注册设置

- 「开放注册」开关，默认关闭。
- 邀请码：
  - 系统中最多只有一个邀请码，可以被多人重复使用，直到被更换。
  - 打开「开放注册」时如果还没有邀请码，自动生成一个，保证开放注册时一定有邀请码。
  - 自动生成的格式：8 位大写字母和数字，去掉容易混淆的字符（0/O、1/I/L），显示为 `K7XM-4QPA`。
  - 操作：复制邀请码 · 复制注册链接（带 `?code=`）· 刷新（二次确认「旧邀请码将立即失效」）· 手动修改（6–32 位字母或数字）。
  - 关闭注册时邀请码保留但不可用，再次开放时继续沿用（也可以随时刷新）。
- 所有修改立即生效，无需重启服务。

### 4.9 快捷键

快捷键只在焦点不在输入框时生效（对话框内的保存除外）。界面上用 `Kbd` 组件提示，并根据系统显示 ⌘ 或 Ctrl。

| 快捷键 | 作用 | 优先级 |
| --- | --- | --- |
| ⌘/Ctrl + V | 粘贴并创建 | P0 |
| ⌘/Ctrl + Enter | 在对话框中保存 | P0 |
| Esc | 关闭对话框 / 清空搜索 | P0 |
| N | 新建 | P1 |
| / | 聚焦搜索框 | P1 |

### 4.10 空状态与提示文案

| 场景 | 文案 |
| --- | --- |
| 列表为空（桌面端） | 大字「按 ⌘ V 粘贴，即刻保存」，小字「或点击『新建』」 |
| 列表为空（移动端） | 「点击右下角 + 开始」 |
| 粘贴了图片或文件 | 「目前只支持保存文本」 |
| 搜索无结果 | 「没有找到包含"xxx"的内容」 |
| 网络错误 | toast「网络异常，请重试」+ 重试按钮 |
| 登录过期 | 跳转登录页，提示「登录已过期，请重新登录」 |

## 5. 非功能需求

### 5.1 兼容性与运行环境

- 浏览器：Chrome / Edge / Firefox / Safari 最新两个大版本；iOS Safari 16+；Android Chrome。
- 访问方式：应用本身按 `http://<服务器IP>:<端口>` 设计；域名和 HTTPS 由部署者在 Nginx 上自行配置。两种方式的差别：

  | 功能 | HTTP / IP 访问 | HTTPS 访问 |
  | --- | --- | --- |
  | 粘贴创建 | ✅ | ✅ |
  | 点击复制 | ✅（降级方案） | ✅ |
  | 「读取剪贴板」按钮 | 隐藏 | ✅ |
  | 登录 Cookie | 不带 `Secure` | 自动带 `Secure` |

- 响应式：最小支持 360px 宽度。
- 界面语言：v0.x 只支持简体中文，文案集中管理，方便以后接入 i18n。
- 主题：浅色 / 深色，默认跟随系统。

### 5.2 性能

- 单用户 1 万条以内时，列表首屏（30 条）接口响应 < 200ms。

### 5.3 安全

| 项目 | 措施 |
| --- | --- |
| 密码 | argon2id 哈希 |
| 会话 | 32 字节随机 token；Cookie 设置 `HttpOnly`、`SameSite=Lax`，请求为 HTTPS 时（包括经 Nginx 转发的 `X-Forwarded-Proto`）自动加 `Secure`；数据库只存 token 的 SHA-256，可在服务端即时吊销 |
| CSRF | `SameSite=Lax` + 所有写操作校验 `Origin` 请求头 |
| 越权访问 | 所有条目接口强制按当前用户过滤；ID 使用随机字符串（nanoid），不用自增数字 |
| 暴力破解 | 登录、注册、初始化接口按 IP 限流（如 15 分钟 10 次）；邀请码和初始化码用常量时间比较 |
| XSS | 文本一律按纯文本渲染，不使用 `dangerouslySetInnerHTML`；不保存 HTML |
| 安全响应头 | 使用 `@fastify/helmet`（含 CSP） |

### 5.4 数据

- 条目永久保存，直到用户自己删除。
- 所有时间以 UTC 毫秒时间戳存储，前端按浏览器时区显示。
- SQLite 开启 WAL 模式。
- 数据库迁移由 drizzle-kit 生成，服务启动时自动执行。

## 6. 技术方案

### 6.1 技术栈

- 前端：React 19、TypeScript、Tailwind CSS v4、shadcn/ui、day.js
- 后端：Node.js、Fastify + TypeScript
- 数据库：Drizzle ORM + SQLite

所有技术优先使用上面指定的框架，UI 组件和插件尤其如此。指定框架覆盖不到的地方，按社区最佳实践选型，**确认后再安装**。

### 6.2 补充依赖（已确认）

| 用途 | 依赖 | 理由 |
| --- | --- | --- |
| 前端·服务端状态 | `@tanstack/react-query` | 无限滚动、乐观更新、窗口聚焦自动刷新都是现成的 |
| 后端·Cookie | `@fastify/cookie` | Fastify 官方插件 |
| 后端·静态资源 | `@fastify/static` | 官方插件，托管前端构建产物 |
| 后端·限流 | `@fastify/rate-limit` | 官方插件 |
| 后端·安全头 | `@fastify/helmet` | 官方插件 |
| 后端·参数校验 | `zod` + `fastify-type-provider-zod` | 前端已安装 zod，前后端共用校验规则 |
| SQLite 驱动 | `better-sqlite3` | Drizzle 支持最成熟的驱动 |
| 密码哈希 | `@node-rs/argon2` | 自带预编译二进制，不需要 node-gyp，Docker 构建省心 |
| ID 生成 | `nanoid` | 短、URL 安全、不可预测 |
| 开发运行 | `tsx` | 直接运行 TS，支持 watch |

以下需求不引入新依赖：toast 使用已有的 shadcn `toast` 组件；URL 识别用一个简单的正则实现。之前列出的 `@fastify/multipart` 因为不再支持文件，已移除。

> 顺带：现有前端模板里的 `date-fns`（和指定的 day.js 重复）、`recharts`、`embla-carousel-react`、`react-day-picker`、`input-otp` 等与本产品无关，建议开发开始时连同对应的 UI 组件一起清理。

### 6.3 架构

- **单体**：Fastify 同时提供 `/api/*` 接口和前端静态文件（SPA 路由回退到 `index.html`）。生产环境只有一个 Node 进程、一个容器。
- **开发**：Vite（5173）把 `/api` 代理到 Fastify（8000），已在 `vite.config.ts` 中配置。
- **定时任务**：进程内定时器，启动时执行一次、之后每小时执行一次，清理软删除超过 24 小时的条目和过期会话。

### 6.4 数据模型

```text
users
  id              text     PK                    -- nanoid
  username        text     UNIQUE COLLATE NOCASE
  password_hash   text
  role            text                           -- 'admin' | 'user'

clips
```

## 7. 部署

### 7.1 方式

- 服务器为 Ubuntu 24.04，项目直接 `git clone` 到服务器，用 `docker compose up -d --build` 启动。
- compose 中只有一个 `app` 服务，把容器的 8000 端口映射到宿主机（监听地址和端口都可通过 `.env` 配置），启动后通过 `http://<服务器IP>:8000` 访问。
- 镜像多阶段构建：构建前端 → 构建后端 → 运行镜像只包含构建产物和生产依赖；以非 root 用户运行；通过 `/api/health` 做健康检查。
- 基础镜像固定为 Node 24 LTS：`node:24-slim`，不使用浮动的 `node:lts` 标签。better-sqlite3 和 argon2 都是原生模块，Node 大版本在某次重新构建时悄悄升级，可能直接导致构建失败；需要升级时手动改一个数字即可。

### 7.2 环境变量（`.env`）

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `ADMIN_INVITE_CODE` | 首次启动必填 | — | 初始化管理员用的一次性码，不少于 8 位；初始化后失效，可以删除 |
| `HOST_BIND` | 否 | `0.0.0.0` | 宿主机监听地址；接入 Nginx 后改为 `127.0.0.1` |
| `HOST_PORT` | 否 | `8000` | 映射到宿主机的端口 |
| `MAX_TEXT_SIZE_KB` | 否 | `1024` | 单条文本上限 |
| `SESSION_TTL_DAYS` | 否 | `30` | 登录有效期 |
| `TRUST_PROXY` | 否 | `false` | 放到 Nginx 后面时设为 `true`，见 §7.3 |

仓库提供 `.env.example`，其中每个变量都带注释。

### 7.3 接入 Nginx（部署者自行配置）

应用不负责域名和证书。之后接入 Nginx 时需要注意：

- 设置 `TRUST_PROXY=true`，否则所有请求看起来都来自 Nginx 的 IP，限流会把所有人一起拦住；应用也无法判断是否 HTTPS。
- 开启 `TRUST_PROXY` 后，建议设置 `HOST_BIND=127.0.0.1`，只允许本机访问应用端口，避免有人绕过 Nginx 直连并伪造 `X-Forwarded-For`。
- Nginx 需要转发 `Host`（用 `$http_host`，保留端口号）、`X-Forwarded-For`、`X-Forwarded-Proto` 请求头。
- Nginx 默认的 `client_max_body_size` 只有 1m，放不下 1 MB 的文本，需要调到 4m 左右。

### 7.4 数据与备份

- 所有数据在 `./data`（挂载到容器的 `/app/data`），只有一个 `easy-cv.db`（运行时还会有 `-wal`、`-shm` 两个附属文件）。
- 备份：`docker compose stop` 后复制整个 `data/` 目录；或在线使用 SQLite 的 `.backup` 命令。
- 不要把 `data/` 放在 NFS 等网络文件系统上（SQLite 的文件锁在上面不可靠）。

### 7.5 运维命令

```bash
# 升级
git pull && docker compose up -d --build

# 重置任意用户的密码（包括管理员），输出一个新的随机密码
docker compose exec app node backend/dist/cli.js reset-password <username>
```
